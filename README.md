# NovelAI Prompt Workbench (非公式)

NovelAI画像生成向けのローカル保存型Chrome MV3拡張です。P0/P1、P2の範囲コメント・連携基盤に加え、**P3のプリセット・グループ切替、P4の画像管理・手動A/B比較、プロンプトシャッフル（役割・ポーズ・カメラ・順序）を実装済み**です。**実NovelAIへの書込みは未検証のため、引き続き無効です。** NovelAIとは提携していません。

## 実装済み

- 日本語名・説明・カテゴリ・タグ・原文・チャンネルのライブラリCRUD、複製、検索・絞込み・ソート、50件ずつの表示。
- ユーザー定義グループと複数候補、ラジオによる排他選択・チェックボックスによる独立トグル、親ON/OFF、編集・削除・並べ替え・折りたたみ。非選択項目の原文も保持します。
- Positive/Negative別の共通コンパイラ・ライブプレビュー・コピー。辞書原本とworkspace snapshotは独立しています。
- 自由入力/構成内原文の範囲コメント・解除、Unicode/特殊構文保持、Undo/Redo、保存・JSON復元。
- **名前付きプリセットの作成・複製・名前変更・編集・上書き保存・削除・検索・選択**。複数グループと自由入力・コメントを一括で復元し、適用を1回のUndoで戻せます。
- プリセットと現在構成との差分・未保存表示、適用前後の両チャンネルのプレビュー、辞書変更/削除・作成元削除の診断、別workspace/新workspaceへの復元。
- IndexedDB自動保存、v1/v2→v3のバックアップ付き原子移行、更新競合・保存エラー、テキストJSON取込/書出し、破損時の復旧dump。

- 現在構成/プリセットからA/Bの固定スナップショットを作成、名前変更・複製・削除・保存/復元。Bの自由入力・コメント・グループだけを独立編集し、1回のUndoで取り消せます。
- プロンプトの文字差分・グループ/選択差分・生成条件差分、各チャンネルのコピー。Seedは文字列、未取得値は不明。「検証不能」「設定不一致」を明示します。
- PNGのファイル選択/ドロップ、SHA-256重複検出、サムネイル一覧、原本保存、画像関連付け、同期ズーム/パン、横並び・重ね合わせ・ピクセル差分。

PNG標準テキストの抽出と手入力を利用できます。**NovelAI固有メタデータは実サンプルが無く未実装・未検証**です。未知の形式はテキストとして保持し、Prompt/Seed/生成条件を推測しません。生成操作、内部API、認証取得、外部送信・同期は実装していません。

## セットアップ

Node.js **22.12+**、pnpm **10.34.5**。実測はNode 24.21.0。依存と権限はP2から追加していません。

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm test
corepack pnpm typecheck
corepack pnpm build
```

`chrome://extensions`で開発者モードをONにして、`.output/chrome-mv3/`を「パッケージ化されていない拡張機能を読み込む」で指定します。既存利用時は拡張とパネルを再読込してください。popupとSide Panelは同じentryを使います。実ウィンドウでのSide Panelドッキングは手動未検証です。

初回は空です。ライブラリとworkspace/グループを作り、「構成に追加」を使います。サンプルは「設定」→「デモを追加」を押したときだけ挿入します。

## プリセットの使い方

1. ワークスペースでグループ、選択、自由入力、コメントを編集します。
2. 「新しいプリセット名」を入力し、「現在の構成をプリセット保存」を押します。
3. ドロップダウンで適用候補を選び、設定差分と「現在/適用後」のPositive・Negativeを確認します。選択だけでは構成を変更しません。
4. 「プリセットを適用」で確認後に切り替えます。未保存の編集がある場合も明示し、**1回の「元に戻す」**で直前の構成・選択・コメント・適用元を復元できます。

ワークスペース上の編集は端末へ自動保存します。プリセットに反映していない編集は「プリセットに未保存の変更があります」と表示します。保存済みプリセットは、辞書や作業中の構成を編集しても勝手に変わりません。

プリセットを編集する場合は、プリセットタブの「適用してグループを編集」または通常の適用後にworkspaceを編集し、「現在の構成で上書き保存」を押します。変更前後を確認して明示的に更新します。名前変更・複製・削除も同じタブから操作でき、検索できます。新規名/名前変更のフォームは保存操作まで未確定です。

適用は対象workspaceのIDとタイトルを維持します。別workspaceでIDが衝突する場合は内部IDだけを安全に再採番し、選択先とコメントを維持します。dirty判定はrootのID/タイトル/更新時刻を除き、順序・全候補・原文・ON/OFF・コメントを比較します。

辞書原文が後から変わったり削除されても、保存済みrawで出力を再現します。診断欄に該当グループ・項目を表示します。作成元workspaceがなくても「新しいワークスペースに復元」を使えます。原文が破損したsnapshotや存在しない選択先、presetへの循環参照は取込みを拒否します。

## 範囲コメント

原文を選択して「選択範囲をOFF」を押します。例: `long hair, black hair, blue eyes`の`black hair`をOFFにすると出力は`long hair, blue eyes`。原文は別spanにそのまま保持し、範囲トグル・Undoで復元できます。

部分選択は単純なカンマ項目の境界に限定します。語/Unicode文字の途中、区切りだけ、既存OFF範囲の重複は拒否します。`{}` / `[]` / `::` / macro / pipe / 改行を含む原文は全文選択または部品トグルを使ってください。

コメント構造がある間は本文が選択可能なreadOnlyになります。本文編集の再開は確認付きで構造を解除します。Undo/Redoは最大30操作のメモリ履歴で、外部サイトの操作は戻しません。

## 保存形式と移行

現在はDB/JSON **schemaVersion 3**です。P0〜P3のv1/v2データを検証して移行します。元の全record/metadataを`migrationBackup:v1`または`migrationBackup:v2`へ退避できたことを確認してから、画像・実験・原本・サムネイルのstoreを追加します。全upgradeは原子的で、失敗時は元のversion/store/dataへ戻ります。旧取込前バックアップも保持します。

「設定」→「移行前バックアップを保存」で旧資産を現形式のJSONに退避できます。JSON v1/v2を受け付け、書出しはv3です。mergeのID/ハッシュ衝突は拒否し、replace前には1世代のバックアップを取ります。

JSONは比較スナップショットと画像メタデータを含み、`imageBinariesIncluded: false`を明記します。**原本とサムネイルは含みません。** 元PNGを別途保存してください。別プロファイルへ復元すると画像欠落を表示し、同一PNGの再取込で既存IDに修復します。画像資産の削除はUndo可能です。バイナリの解放は現在の資産・Undo/Redo・取込前バックアップを保護し、参照されないものだけ明示操作で行います。

JSONはUTF-8 10MiB、全snapshot/spanを含む合計10000レコード、深さ32まで。snapshot内部のIDは独立scopeで検証します。コメントやpreset bindingは保存しますが、画像バイナリ・Undo履歴・一時site ticketは含めません。

破損DBを自動初期化しません。移行失敗時は原DBを残し、読み取れた復旧snapshotをダウンロードできます。循環・BigInt・過深な不正値は診断markerにします。これは通常import用の資産JSONとは別です。壊れた旧DBや不足storeは自動修復せず、未知の将来版と旧ビルドへのダウングレードも対象外です。閉じる前に「保存済み」を確認し、保存失敗/競合時は作業データをJSONへ退避してください。

## 手動A/B比較の使い方

1. 「比較」で現在のワークスペースまたは保存済みプリセットを選び、比較を作成します。A/Bの原文・選択・合成済みPositive/Negativeを固定します。元構成は変更しません。
2. 「Bのグループ・タグを編集」でBだけの変更案を作り、プレビューして確定します。別プリセットを選んで「比較元からBを再固定」も可能です。Bの再固定は旧画像の関連付けを外し、設定は保持します。
3. 各スロットで生成条件を手入力し「設定を保存」を押します。空欄は不明、Seedは桁落ちしない文字列です。Image2Image/参照画像を使わない場合も「不使用」と記録し、モデル固有の追加条件はJSONで記録します。
4. 差分を確認し、A/BそれぞれのPromptをコピーします。NovelAIでユーザーが手動生成し、保存したPNGを該当スロットに取り込みます。自動生成・設定の自動操作はありません。
5. 画像/Prompt/設定を比較します。PNGに生成情報が無い場合は画像情報を手入力できます。画像側の設定をスロットへ採用するには明示確認が必要です。

### タグの重みをスライダーで比べる

「Bのグループ・タグを編集」で原文のタグ1つを選択し、「重みを調整」を押します。自由入力のPositive/Negativeと、グループの「この候補のタグを編集」で使えます。ワークスペースの原文編集でも同じ操作が可能です。

- スライダーは **0〜2、0.05刻み**。小数第2位までの数値入力、変更後プレビュー、標準の1に戻すボタンがあります。例: `blue eyes` → `1.4::blue eyes::`。0も数値重みとして残し、タグの削除やコメントOFFにはしません。
- 「重みを反映」で編集欄に確定し、「Bの変更を確定」で比較用に保存します。調整中はBの確定を止め、未反映の重みを取りこぼさないようにします。Undo/Redoで戻せます。
- 既存の数値重みは `1.4::blue eyes::` 全体を選んで再調整できます。同じタグが複数あっても選択した箇所だけを変え、前後の文字列・空白を保持します。
- 複雑な入れ子・braces/brackets・pipe・macro・エスケープ・改行を含む欄、複数タグの一括重み、0〜2以外の既存重みは自動編集の対象外です。対象を独立した部品にするか本文で編集してください。コメント構造がある間は、構造を解除してから調整します。

生成条件を合わせてA/Bを手動生成し、各PNGを取り込むと、比較画面上部の画像ビューで横並び・重ね合わせ・ピクセル差分を確認できます。Bを変更して確定すると旧B画像の関連付けを外します。数値重みのモデル別の効果や実NovelAIでの生成結果は未検証です。

PNGは20MiB、各辺8192px、合計16,777,216画素まで。PNG署名・チャンク境界・CRC・終端とブラウザのデコードを検証します。APNG/JPEG/WebPは未対応です。標準`tEXt/zTXt/iTXt`のテキストは展開後も合計256KiBまで、128チャンクまで。HTMLとして描画しません。公式保存NovelAI PNGのフィールド対応は`codex/05`に従い実サンプル確認後に追加するparser interfaceとしています。テスト用の明示的なworkbench形式のみ構造化Prompt/Seed等の取得を検証しています。

表示はA/B共通倍率・位置でパン/ズームできます。矢印キーでもパンできます。異なる寸法は警告し、ピクセル差分は同寸法のみ、またはユーザーが「BをAの幅・高さへ変形」を選んだ場合のみ計算します。Canvas高品質補間で縦横比が変わる場合があります。差分は各画像4,194,304画素まで、ブラウザがデコードしたsRGB RGBAの絶対差です。原本は変更しません。

比較内容は自動保存します。B編集案は未確定と表示し、画面切替/再読込時に確認します。設定/画像注記のフォームは各保存ボタンで確定してください。画像保存に失敗すると未保存エラーを表示し、再試行できます。閉じる前に保存状態を確認し、必要なら画像ライブラリの「画像原本を保存」とJSONで退避してください。

## NovelAIとの接続

拡張更新後に画像ページを再読込し、「NovelAIの接続を確認」でタブとチャンネルを明示選択します。観測済みの単純なProseMirror DOMが一意なら、その欄だけを読み取れます。未知の装飾・macro DOMや重複候補は推測しません。

**実NovelAIの挿入/置換は無効のままです。** P2時点で公開ページの空2欄をContent Script経由で自動読取りしましたが、ログイン後UIと書込み・内部状態保持は未検証です。プリセット適用・グループ切替はローカルだけで、サイトへ自動送信しません。コピーを使ってください。

fixture上の書込みフローは対象タブ固定→read/prepare→変更前後確認→明示apply→CAS/readbackです。成功を実サイト対応の根拠にはしていません。権限は`sidePanel`のみで、tabs/activeTab/host_permissions/backgroundを追加していません。

## プロンプトシャッフル

同じプロンプトで構図が似通うのを避けるため、**キャラクターの外見（固定プロンプト）は変えずに**、役割・ポーズ・表情・カメラ・左右順だけを入れ替えます。「シャッフル」タブから使います。

1. 「＋ プロファイル」を作成し、キャラクターを追加して固定プロンプト（例: `girl, blonde hair, blue eyes, white dress`）を入力します。可変プロンプトはカテゴリ別に入力し、シャッフルがそのカテゴリを決めたときだけ置き換わります。
2. 役割テンプレート（例: Pointing — 行動する側 `standing, source#pointing at another` / 行動される側 `sitting, target#pointing`）やポーズセット・候補プール・カメラプリセットを登録します。「標準テンプレート・候補を追加」で汎用例を入れられます（明示操作時のみ）。
3. 対象カテゴリ、方式（Pure Random / Shuffle Bag / Weighted Random）、直前・直近N件の回避、シャッフルSeed、モデルを選びます。
4. 「Shuffle Now」で結果を確認します。役割は「A=行動する側、B=される側」と「B=行動する側、A=される側」のように**組で**入れ替わり、Shuffle Bagでは両方を使い切ってから次の巡回に入ります。「次のシャッフル結果のプレビュー」で次の差分も確認できます。
5. 各欄（ベースPrompt・キャラクター別Prompt/UC）をコピーしてNovelAIに貼り付けます。サイト連携できる環境では「Apply（反映プレビュー）」→「確認してApply」、元に戻すときは「Restore」です。

- 合成は毎回、ワークスペースの出力とキャラクター定義から計算し直すため、何度適用してもタグは増えません。ユーザーが書いたタグは削除せず、矛盾の可能性だけ警告します。NovelAIの `||a|b||` ランダマイザーは改変しません。
- 同じ設定・同じシャッフルSeed・同じステップ数で同じ結果を再現します。NovelAIの生成Seedとは別で、生成Seedは読み書きしません。履歴（最大50件）から過去の結果を再適用できます。
- 生成回数に応じた切替: 間隔（毎回/3/5/10/任意）を選び、「生成完了を手動で記録（+1）」で数えると、規定回数でシャッフルします。生成状態を確認できるサイト連携（現在はローカルfixtureのみ）では「自動シャッフルを開始」で、成功したジョブ数に応じて次回用プロンプトを書き換えます。生成ボタンは押さず、生成中は書き換えず、サイト側で編集されていれば上書きせず停止します。
- **実NovelAIでは**: キャラクター欄・モデル表示・生成状態のDOMが未検証のため、反映・自動検知は無効です（接続すると「非対応」と理由を表示します）。コピーと手動記録を使ってください。Character Positionsの座標は変更しません。
- 設定はIndexedDBに保存され、JSONバックアップに含まれます。シャッフル設定だけのエクスポート/インポート（履歴なし）もできます。読み込めないシャッフル設定は隔離し、ライブラリは通常どおり起動します。

詳細: [docs/shuffle/architecture.md](docs/shuffle/architecture.md)、[データモデル](docs/shuffle/data-model.md)、[Site Adapter](docs/shuffle/site-adapter.md)、[テスト計画](docs/shuffle/test-plan.md)、[制約](docs/shuffle/limitations.md)。

corepack pnpm fixture
# UI: http://127.0.0.1:4173/tests/fixtures/index.html
# P2 React controlled mock: http://127.0.0.1:4173/tests/fixtures/site.html

通常のE2Eから実NovelAIへは通信しません。実content scriptのテストでも、NovelAI URLの応答をPlaywrightの模擬HTMLへ差し替えます。fixture/profileは製品bundleに入りません。制限されたLinux環境での今回のコマンド:

```bash
LD_LIBRARY_PATH=/tmp/nai-chromium-deps/root/usr/lib/x86_64-linux-gnu \
PLAYWRIGHT_BROWSERS_PATH=/tmp/nai-pw-browsers corepack pnpm test:e2e
```

（root権限がない環境では `apt-get download libnspr4 libnss3 libasound2t64` と `dpkg -x` で共有ライブラリを展開し、`LD_LIBRARY_PATH` に指定します。）

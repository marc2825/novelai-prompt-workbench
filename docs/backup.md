# バックアップと復元

データはChromeプロファイル内のIndexedDBにだけ保存されます。拡張機能の削除・プロファイル削除・ブラウザデータ削除で消えるため、定期的に**完全バックアップ**を保存してください。

## 3つの形式

| 形式 | 作成場所 | 内容 | 用途 |
|---|---|---|---|
| **完全バックアップZIP**（推奨） | 設定 → 完全バックアップ | 全テキスト資産・設定・比較・Experiment Lab・シャッフル・タグ辞書・画像メタデータ **＋画像原本・サムネイル** | 別プロファイル/別PCへの移行、完全な復元 |
| JSONバックアップ | 設定 → JSONバックアップ | 上記のうち画像原本・サムネイル以外 | 軽量な退避、旧版との互換 |
| Experiment Lab ZIP | Experiment Lab → ZIP | 1つの実験・条件CSV・その実験の画像原本 | 実験の共有・分析。**アプリ全体のバックアップではない** |

Undo履歴・サイト連携の一時情報（反映前原文・確認チケット）はどの形式にも含みません。

## 完全バックアップZIPの形式（manifestVersion 1）

無圧縮（stored）のZIP32、最大2GiB。

```text
spellbinder-backup-YYYYMMDD-HHMMSSZ.zip（0.2.0までは nai-prompt-workbench-backup-…）
├── manifest.json            形式・版・件数・全ファイルのサイズとSHA-256
├── data.json                通常のJSONバックアップ（単独でもJSONインポート可能）
├── images/<image-id>.png    画像原本（SHA-256 = ImageRecord.hash）
└── thumbnails/<image-id>.png  保存済みサムネイル（256px以下）
```

`manifest.json` の主な項目:

- `format: "nai-prompt-workbench-full-backup"`, `manifestVersion: 1`, `schemaVersion: 3`（データ形式）, `exportedAt`, `generator {name, version}`
- `data {path, bytes, sha256}`
- `images[] {id, original {path, bytes, sha256}, thumbnail {path, bytes, sha256}}`
- `missingImages[]` — 書出し時に原本が端末に無かった（または内容がメタデータと一致しなかった）画像ID。メタデータだけを含み、復元先では欠落として表示されます（同じPNGを再取込すると修復）。
- `counts` — ライブラリ・カテゴリ・ワークスペース・プリセット・比較・画像・Lab・シャッフル（プロファイル/キャラクター/テンプレート/履歴）の件数。タグ辞書は旧版の厳格なmanifest検証と互換にするため `counts` に含めず、`data.json` 内にだけ持つ（プレビューは `data.json` から件数を表示）

書出しは画像を1枚ずつ読み、SHA-256を記録値と照合してから含めます。ZIPは保存済みBlobを参照して組み立てるため、画像全体をメモリに複製しません。

### 書出しの一貫性（issue #20）

書出しは**開始時点の画面のデータ**（スナップショット）に固定します。書出し中に編集・元に戻す・別の画面での保存が起きても、`data.json` と画像は開始時点のものです。

- 画像は、スナップショット側の記録（ハッシュ・寸法・サイズ）と一致するものだけを含めます。取り込んだばかりで未保存の画像は、開始時に参照を確保するため、途中で元に戻しても欠けません。
- 一致する原本が見つからない画像は `missingImages` に入れ、完了メッセージに**画像名**を表示します。
- 書出し中は「画像バイナリを整理」を実行できません。

### 保存エラー時の退避（issue #18）

保存エラー（容量不足、別の画面との競合など）の間も、完全バックアップの**書出し**はできます（復元はできません）。画面上部の「未保存の変更を含めて完全バックアップを保存」、または設定の「完全バックアップをZIPで保存」を使います。DBには何も書き込まず、画面上の未保存の変更と、未保存の取込画像（この画面のメモリにある原本・サムネイル）を含めます。作ったZIPは通常の完全バックアップとして、別のプロファイルでも復元できます。

## 平文と暗号化（issue #33）

**完全バックアップZIPとJSONバックアップは暗号化されていません。** プロンプト・画像・生成条件・メモがそのまま入っており、ファイルを開ける人は誰でも読めます。端末の中だけに保存しても、ファイルとして書き出した後の扱い（共有・クラウド・USBメモリ）は利用者に委ねられます。

人に渡す・クラウドに置く場合は、完全バックアップで「パスワードで暗号化する」を選びます。

- 形式: `spellbinder-backup-YYYYMMDD-HHMMSSZ-encrypted.nwbenc`。先頭8バイト `NAIWBENC`、ヘッダ長（uint32 BE）、ヘッダJSON（`format: "nai-prompt-workbench-encrypted-backup"`, `version: 1`, `contents: "full-backup-zip"`, `kdf {PBKDF2, SHA-256, iterations, salt}`, `cipher {AES-GCM, 256, chunkBytes, noncePrefix}`, `plaintextBytes`）、続いて暗号化した完全バックアップZIPのチャンク。
- 鍵: パスワード（NFC正規化）から PBKDF2-HMAC-SHA-256（既定60万回、ランダムな16バイトのsalt）で AES-256 の鍵を作ります。ブラウザ標準のWeb Cryptoだけを使い、独自の暗号は使いません。
- 暗号化: ZIPを4MiBずつ AES-256-GCM で暗号化します（2GiBまでのファイルを一度にメモリに載せないため）。各チャンクのnonceは「ランダムな7バイト＋チャンク番号＋最後のチャンクか」で、ヘッダ全体を追加認証データにします。誤ったパスワード・ヘッダや途中のデータの改変・切り詰め・追加・チャンクの入れ替えはすべて検出し、何も書き込みません。
- 読込時の検証: ヘッダの形式・版・反復回数（10万〜1000万回）・チャンクサイズ・元のサイズとファイルサイズの一致を、鍵を作る前に確認します。復号した後は通常の完全バックアップと同じ検証を行います。
- パスワードは保存・記録しません。**忘れると誰も復元できません。** 8文字以上、確認入力と一致が必要です。暗号化・復号はチャンクの間で中止できます。
- 暗号化しないZIPは従来どおりです（形式・互換性の変更なし）。

## 復元の流れ

1. **検証（書込みなし）**: ZIP構造 → manifest → data.json（サイズ・SHA-256・通常のJSONと同じ全スキーマ検証）→ 件数・画像の相互参照 → 全画像（CRC・SHA-256・PNG構造・寸法、サムネイル）。1件ずつ読み込みます。
2. **プレビュー**: 現在とバックアップの件数、検証済み画像の件数と容量、欠落画像、空き容量の目安を表示。
3. **方法の選択**: 「全置換」（移行・完全復元。推奨）または「追加」（ID・画像ハッシュの重複はエラー）。
4. **確認して復元**: 確認ダイアログの後、データ・取込前バックアップ（1世代）・全画像を**1つのIndexedDBトランザクション**で保存します。保存直前に画像を再検証します。容量不足・途中の失敗では何も書き込まれず、画面も元のデータのままです。
5. 成功後は「元に戻す」1回で復元前の状態に戻せます（画像原本は削除されず、後で「画像バイナリを整理」で解放できます）。

### 拒否するもの

- ZIP64・分割・暗号化・データ記述子・**圧縮エントリ**（展開しないためZIP bombは成立しない）
- 不正なパス（`..`・絶対パス・バックスラッシュ・想定外の文字）、名前の重複、ローカルヘッダと中央ディレクトリの不一致、エントリの重なり
- manifestにないファイル、manifestにある不足ファイル、想定外の名前（`images/<UUID>.png`・`thumbnails/<UUID>.png`・`manifest.json`・`data.json`以外）
- 未知のmanifestVersion / schemaVersion、件数の不一致、`__proto__`等の危険なキー、不正なJSON
- SHA-256・CRC・サイズ・寸法の不一致（改変・破損）
- 端末に**同じ画像IDで別内容**のバイナリが既にある場合（Undo履歴・取込前バックアップが参照している可能性があるため、上書きせず中止）
- Experiment LabのZIP（専用のメッセージで案内）

### 上限

ZIP 2GiB、エントリ30,000、manifest 8MiB、data.json 20MiB（JSONと同じ）、画像1枚20MiB・各辺8192px・16Mpx、サムネイル1MiB・256px。

データ本体（payload）の上限は10MiB（保存時に検査）、それを含むファイル（JSONバックアップ・`data.json`・シャッフル設定・Lab JSON）の上限は20MiBです（issue #19）。保存できたデータは必ず書き出して読み込めます。書出しは10MiB以内なら読みやすい整形済みJSON（旧版でも読める）、超える場合は改行なしのJSONになります。

## 既知の制限

- 2GiBを超える画像を持つ場合は完全バックアップを作成できません（不要な画像の削除、Lab ZIP・原本の個別保存を併用）。
- 検証後に選択したZIPファイルを変更・削除すると、保存時の再検証または読取りが失敗し、何も書き込まずに中止します。
- 「追加」モードは同じ画像（同一ハッシュ）を共有するデータの統合には対応しません（エラー）。全置換を使ってください。
- 旧ビルドへのダウングレード（新しいmanifestVersionの読込）は対象外です。

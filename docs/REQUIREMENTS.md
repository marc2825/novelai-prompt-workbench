# 要件定義書（Product Requirements Document）

- バージョン: 1.0 / 作成: 2026-11-03
- 製品仮称: NovelAI Prompt Workbench
- 対象: NovelAI **画像生成**を頻繁に使い、構造化されたプロンプトを再利用したい個人
- デスクトップChrome優先。Firefox/Safari/モバイルは初期対象外
- この文書の必須語: **MUST**=受入必須、**SHOULD**=高優先、**LATER**=後続フェーズ

## 1. 目的と背景

公式Prompt Chunksは `@`呼出し・フォルダ整理・入れ子マクロ・サーバー保存に対応する。本製品は重複する単純辞書ではなく、(a)画像/日本語から探せる、(b)グループ切替・排他切替が即時反映される、(c)コメントアウトが非破壊、(d)複数グループをプリセットとして切替、(e)変更1点に注目した手動A/B比較を行う、を価値とする。

## 2. ユーザーストーリー

- US01: 髪型・衣装などの部品を日本語の名前と原文で保存し、数千件から検索したい。
- US02: 登録プロンプトをクリック/ホットキーで現在の構成へ追加したい。
- US03: 髪型は一つだけ有効、照明や背景は複数同時有効にしたい。
- US04: いったんOFFにしても、本文・強調記号・順序を完全に残したい。
- US05: 「制服」「私服」等で複数グループの状態を一括切替したい。
- US06: 変更箇所だけ異なるA/Bのテキストを生成し、同一Seed・設定で手動生成したPNGを並べて確認したい。
- US07: ネット接続なしでもライブラリを使え、インポート/エクスポートで移行したい。
- US08: NovelAI UI変更時でもデータ消失や意図しない送信が起きないようにしたい。

## 4. UI要件

- Side Panelのタブ: `ライブラリ` / `ワークスペース` / `プリセット` / `比較` / `設定`。
- ライブラリ: 検索欄、カテゴリ、タグ、追加、編集、複製、削除、サムネイル。リストは仮想化を検討。
- ワークスペース: positive/negative別、折畳みグループ。`multi`はチェックボックス、`exclusive`はラジオ相当、親ON/OFFは別スイッチ。無効項目は灰色+取消線だが内容は保持。
- ライブプレビュー: **出力される文字列だけ**を表示。OFF項目は出力に含まない。コピー・NovelAIに反映ボタン。
- コメントアウト: 構成部品レベルをP1で実装。テキスト選択範囲はP2で独立ブロック化してOFF、Undo/Redoで原状復帰。
- プリセット: 適用前に変更プレビュー。ライブラリ原本を更新しない。
- 比較: A/Bプレビュー、差分、同一Seed/モデル/設定確認チェック、2つの画像取込、画像比較。生成操作はユーザー本人がNovelAI画面で行う。
- 不確かな状態やサイト連携失敗時には `コピー` を必ず使える。

## 5. コメントアウト/トグルの厳密な動作

- 「コメントアウト」は**プロジェクトの構造化編集状態**。送信文字列にコメント構文を混ぜない。
- OFFと削除を別操作にする。OFFにしたデータは保存され、再ONで完全に復元。
- `exclusive`: グループON時、選択0件または1件。選択変更時も他候補を削除しない。
- `multi`: 各部品を独立してON/OFF。グループOFF時は子のON/OFFを保存。
- 複数チャンネル間で任意に部品を移動したときは明示操作とする。
- `raw`はNovelAIの強調 `{}`、抑制 `[]`、数値構文、`|`、`!macro:...!` を含み得るため、単純なカンマ分割でタグへ分解しない。
- 原文の中に `,` がある場合も原文をそのまま保持。ライブラリ項目境界でだけ区切り文字を挿入。

## 6. プリセットの意味

- プリセットは workspace ID、グループON/OFF、各部品の選択状態・順序・ローカル上書き、自由入力部分の**スナップショット**。
- デフォルトはスナップショット適用。登録辞書の内容を後から編集した場合に過去プリセットの出力が勝手に変化しないよう、解決済み原文も記録。新しい辞書参照に更新する操作は明示。
- 名前重複は許容しつつ、IDは一意。参照先が消えたときは保存済み原文で復元し警告を表示。

## 7. A/B比較の意味

- A/Bを一つの実験とし、両方についてコンパイル済みpositive/negative、Seed（文字列で完全保存）、モデル、Steps、Sampler、Guidance、解像度、その他設定のスナップショットを記録。
- 比較条件に差があれば、プロンプト変更以外の要因として警告（「厳密比較」バッジは不可）。未確認の設定も警告。
- 画像はユーザーが公式保存ボタンで保存したPNGをインポート。メタデータ欠落時は推測せず「未確認」。
- 同一Seed・設定でも出力が常にピクセル一致するとは保証しない。
- 未承認のAPI呼出し/自動画像生成/同時大量生成はしない。詳しくは `docs/AB_COMPARISON.md`。

## 8. 非機能要件

- NFR01: 個人データは原則ローカル、外部送信/分析/トラッキングはゼロ。ユーザーの明示操作でのみNovelAIにプロンプトを反映。
- NFR02: 認証情報、cookie、トークンを取得・保存しない。必要最小権限。
- NFR03: 1000件程度のライブラリ検索で体感遅延がない（ベンチ目標 p95 < 200ms、ハード依存）。
- NFR04: 起動/閉じる/サイト再読込でデータが失われない。DB書込失敗を通知する。
- NFR05: インポートは破損、未知バージョン、巨大入力、重複IDを安全に扱う。
- NFR06: 将来NovelAI DOMが変更されても失敗を明示し、既存入力欄を破壊しない。
- NFR07: ユーザー入力文字列をHTMLとして実行せず、XSSを防ぐ。
- NFR08: 変更時の検証可能性: 単体/統合/ブラウザ手動チェックを分けて報告。

## 9. 初期版の非対象

- 無制限・無人の画像生成、隠れたAPI/内部ストアへの介入、NovelAI設定の自動取得を事実として仮定、他サイトに横展開、ログイン・課金処理、画像認識AI、クラウド同期。
- NovelAIサイトの任意DOMと公式Prompt Chunksの双方向同期は調査後に可否判断。

## 10. 受入シナリオ

- AC01: 髪型3件をexclusiveグループへ入れ、A→Bで出力はBのみになる。
- AC02: グループをOFF→ONにしても、元の選択Bは維持。
- AC03: multiグループでAとBをON、BのみOFF、Aだけ出力。
- AC04: 部品の `{{hair}}` などの文字列はOFF/ON後も完全に一致。
- AC05: positive/negativeは混ざらない。
- AC06: スペース、カンマ、Unicode（日本語名/絵文字）を含むライブラリ名でも検索/保存可能。
- AC07: 保存→拡張再起動→同じworkspaceの出力を得られる。
- AC08: P1のJSONエクスポート→全削除→インポートでテキスト資産を復元。
- AC09: 不正なJSONでDBが壊れず、ユーザーに原因が提示される。
- AC10: Preset A→B→AでAのスナップショットに一致。
- AC11: プリセット適用はライブラリ原本を変えない。
- AC12: 1000件データで検索操作と選択に支障がない。
- AC13: NovelAIが開かれていない場合、反映は失敗を表示してコピーできる。
- AC14: 内容上書きは確認必須。未確認DOMには書き込まない。
- AC15: A/BのSeed/モデル/設定が一致しない場合「厳密比較不可」を表示。
- AC16: メタデータなしPNGは表示できるが設定値を推測しない。
- AC17: アプリが生成操作を自動送信しない。

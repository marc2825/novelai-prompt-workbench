# Prompt Shuffle — 制約・未検証事項

## 実サイトで動作しないこと（2026-11-14時点）

- **実NovelAIへの書込み（Apply/Restore/自動シャッフル）は無効**。製品の adapter は既存方針どおり読取り専用。キャラクター欄・モデル表示・生成状態のDOMは未調査で、推測したセレクタは入れていない。実サイトでは「シャッフル結果を各欄ごとにコピー」して手動で貼り付ける。
- **生成回数の自動検知は実サイト非対応**。代替は「生成完了を手動で記録（+1）」。規定回数でシャッフルのみ行い、サイトは変更しない。
- **Character Positions の座標は変更しない**（全adapterで `positions.supported: false`）。位置シャッフルは「キャラクター欄の順序」と、任意の補助テキスト（左/右）だけ。補助テキストの効果は未検証で、既定は空。
- モデルは実サイトから検出しない。プロファイルでユーザーが選ぶ（未選択時は6人上限で保守的に検証、|構文は不使用）。

## 公式ドキュメント上の不確定点

- V4.5 のキャラクター上限は未記載 → V4と同じ6人で制限（`documentedMaxCharacters: null`）。
- V5 の位置グリッド仕様は未記載。V3系でのキャラクター欄・|構文は記載なし → V3ではキャラクター出力をエラー扱い。
- `source#`/`target#`/`mutual#` は公式に「常に信頼できるわけではない」。対応タグを生成しても意味的整合性は保証されない。
- V4/V4.5のトークン上限（T5で約512）は数えていない。非ASCII文字の警告のみ。
- Randomizer `||…||` は生成ごとにNovelAIが選ぶため、シャッフルSeedでは再現できない（シャッフル側は文字列を改変せず保持するだけ）。

## 機能上の制約

- 割当の列挙とBagは720通りまで。超える場合は段階的サンプリング（直前と同じ割当のみ回避、均等性は保証しない）。
- 直近N件回避は構図署名の完全一致のみ（最大20件、8回再抽選。見つからなければ警告して重複を許可）。類似度判定はしない。
- 矛盾検出は単純なカンマ区切りタグの照合による警告だけ。`{}`・`[]`・`::`・`|`・マクロを含む断片は解析しない（削除・書換えもしない）。固定プロンプト内のタグはロックしない（固定タグ欄を使う）。
- ロールの「決めるカテゴリ」とプロンプト内容の整合はユーザー設定に依存する（例: ポーズを含む役割は「ポーズ」も決めるカテゴリに入れる）。
- 復元用の反映前原文・最後に書いた値はパネルを閉じると消える（DBに保存しない既存方針）。タブ・ドキュメント・プロファイルごとに分離され、NovelAIのページを再読込すると旧ページの原文はコピー専用になる（Restoreはできない）。
- 自動シャッフルは開始時の設定で固定される。実行中にシャッフル設定・キャラクター・テンプレート・候補・カメラ・ベースプロンプトのどれかを変えると停止するので、確認して開始し直す。
- 自動シャッフルの「開始」状態はパネル再読込で解除される（意図的。間隔設定は保存される）。サイドパネルを閉じている間は数えない。
- 連続したシャッフルは1回のUndo単位。Undoはサイトを戻さない。
- 自動シャッフルの回数カウントはパネル側のメモリ。規定回数より多く完了が届いても1回だけシャッフルする。
- 複数パネルの同時自動シャッフルは content script のlease（15秒）で1つに制限。別タブのカウントは混ざらない（対象タブ・document固定）。
- 未実装: プリセットごとのプロファイル保存、役割ペアの直接禁止UI、バリエーション数推定、キャラクター欄の自動追加/削除。
